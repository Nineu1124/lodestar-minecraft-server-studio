# Lodestar · Minecraft Server Studio

一个为 Minecraft 整合包服主设计的**纯本地 Web 管理面板**。不需要数据库、不需要 Node.js、不把服务端文件上传到云端；启动一个 Python 进程后，在浏览器中管理多个 Minecraft 服务端。

> 面板默认只监听 `127.0.0.1:8765`。SakuraFRP、路由器端口转发或防火墙只应放行 Minecraft 游戏端口，**不要映射 8765 面板端口**。

## 已实现功能

- ZIP 服务端压缩包导入向导：安全检查、嵌套根目录识别、解压进度与导入完成后自动启动
- 从原启动脚本中提取真正的 `-jar` / Forge 参数目标，自动识别 Luminara、Arclight、Mohist 等混合端
- 一键推荐或自定义开服：Java、Xms/Xmx、端口、人数、视距、难度、正版验证、白名单与 EULA
- 一键开服任务：识别可靠的版本元数据、匹配 Java、安装官方 Forge/NeoForge/Fabric 核心，再等待完整游戏状态就绪；支持取消和失败重试
- FTB 官方入口：按项目/版本 ID 下载服务端文件，校验官方哈希并自动安装，不必手工使用作者安装器
- 多服务端导入、切换与本地配置
- 自动检测 Forge、NeoForge、Fabric、Paper、Purpur、普通服务端 JAR 和 BAT/CMD/SH 启动脚本
- 为不同实例分别设置 Java、`Xms`、`Xmx`、启动方式和外网地址
- 启动、正常保存停服、重启与带二次确认的强制停止
- 浏览器实时查看 `logs/latest.log`，执行任意 Minecraft 服务端命令
- 常驻可搜索指令库：状态、世界、玩家、名单、规则、公告与维护共 30 余项常用指令
- Mod 和插件上传、启用、停用、移入回收站和恢复，并读取 Fabric/Forge/NeoForge/Bukkit 元数据
- 安全文件管理器：浏览、上传、下载、重命名、文本编辑、修改历史与可恢复删除
- 编辑经过校验的常用 `server.properties`
- 白名单、OP、踢出、封禁与解封玩家
- 实时调整时间、天气、难度、常用游戏规则，并发送全服公告
- 在线创建世界 ZIP 备份，自动执行 `save-off` / `save-all flush` / `save-on`；停服后可一键恢复且保留恢复前版本
- 按小时自动备份、每天定时正常重启（默认关闭，可按实例配置）
- CPU、内存、运行时间与磁盘空间监控
- Java/加载器/Mod/日志信号诊断，浏览和下载崩溃报告，并自动归类客户端 Mod、端口、内存、Java 与依赖错误
- 暖纸色工作台与深林色夜间主题，紧凑概览、分组侧栏、手机导航与清晰的维护/断线提示
- 8 张原创体素插画覆盖首页、栏目页、空状态和导入向导；素材与完整生成提示词见 [`docs/ART_UPDATE_2026-09-05.md`](docs/ART_UPDATE_2026-09-05.md)
- Host、Origin、路径和文件名校验；配置修改前自动备份

## 系统要求

- Windows 10/11，或带 Python 的 Linux/macOS
- Python 3.11 或更高版本
- 与整合包匹配的 Java 版本；Windows x64 在受支持的自动流程中可下载便携 Java，Linux/macOS 需自行安装对应版本
- 现代浏览器

项目后端只使用 Python 标准库，没有第三方 Python/Node 依赖。

## 快速开始

### Windows

双击：

```text
启动面板.bat
```

浏览器会打开 <http://127.0.0.1:8765>。已有实例直接点“一键开服”。第一次点击侧栏“导入服务端”，选择服务端 ZIP，检查后保留“一键推荐”，确认内存/端口，并亲自勾选 EULA 与信任下载，再点“一键开服”。准备过程会显示在页面中，不需要手工安装 Java 或切换到 CMD 输入命令。

FTB 包可以直接选“FTB 官方整合包”，填写项目 ID、新目录、内存和端口；版本 ID 留空选择官方稳定发布版，首次解析后固定版本，失败重试不会偷偷升级。例：FTB Evolution 项目 ID `125`，本次验证版本 ID `100487`。详细范围及实测见 [`docs/ONE_CLICK_2026-09-06.md`](docs/ONE_CLICK_2026-09-06.md)。

更新后需要重新启动面板进程，再在浏览器按 `Ctrl+F5` 刷新。若旧面板仍托管游戏服，请先通过旧面板正常停服；不要直接结束 Java 进程。仅关闭浏览器不会停止面板。

### Linux / macOS

```bash
chmod +x start.sh
./start.sh
```

也可以直接运行：

```bash
python server.py
```

## 导入服务端压缩包

选择 ZIP 后，Lodestar 会先读取中央目录，不会直接解压。检查通过后会显示游戏版本、加载器、真正的服务端根目录、解压体积、Java 建议和启动文件。最后一步可以选择：

- **一键推荐**：对有可靠元数据的 Forge/NeoForge/Fabric 作者服务端包，自动匹配实际 Java 版本，缺少运行时则下载便携版，缺少核心则安装固定版本。GTNH 保留作者的 `java9args.txt`。混合端保留原核心，不会被替换成普通 Forge。
- **自定义**：在解压前确认内存、端口、人数、视距、难度、正版验证、白名单和启动文件。选择标为“自动”的目标时仍会自动准备；指定脚本/JAR 时保留手动选择。已导入实例可在“配置与启动”关闭“自动准备”以完全保留手动启动配置。

“一键”不表示绕过协议：首次必须明确同意 Minecraft EULA，并信任将运行的整合包代码及依赖下载。也不表示可以自动把任意客户端包转成服务端：仅有客户端 manifest、未知加载器版本或缺少可靠元数据时，需要作者服务端包或明确的人工配置。

导入器拒绝绝对路径、`..` 路径穿越、符号链接、加密包、超量文件和超过安全体积上限的压缩包。解压先写入独立临时目录，成功后才原子移动到最终目录。支持压缩包根目录就是服务端，也支持 `整合包/fuwuduan/...` 这类嵌套结构。

## 导入已解压服务端

导入的是**服务端根目录**，通常能看到以下文件中的至少一种：

- `server.properties`
- `eula.txt`
- `run.bat` / `start.bat`
- `server.jar` / `paper-*.jar` / `fabric-server-launch.jar`
- `libraries/net/minecraftforge/.../win_args.txt`

导入已解压文件夹时，面板记录路径，不复制整个目录；选择立即启动后，会在原目录按上述流程准备缺少的核心与依赖。实例配置保存在 `data/settings.json`，该文件已被 `.gitignore` 排除，不会意外提交个人路径。

开服准备可取消；若本任务已启动游戏进程，会尝试正常保存并停服，不强制结束其他实例。已导入的实例失败后，直接再次点“一键开服”。已通过校验的下载会复用，中断的核心安装会重试。不要删除实例或重新导入到同一个已有目录。首次下载可能耗时较长；安装日志位于服务端 `.lodestar/install.log`，便携 Java 缓存在面板 `data/bootstrap-cache`，不会修改系统 PATH。

## 启动方式与内存

自动检测优先级大致为：Forge/NeoForge 参数文件、适配的 JAR、启动脚本。如果自动结果不正确，可以在“配置与启动”中手动选择。

直接运行 JAR 或 Forge/NeoForge 参数文件时，Java 9+ 使用原生 `@user_jvm_args.txt` 解析多参数行、引号和注释；Java 8 使用兼容解析。面板配置的 `-Xms`、`-Xmx` 放在该文件之后，覆盖文件里的内存设置。通过 BAT/SH 启动脚本时，内存由脚本自身控制。

进程归属由面板启动记录、PID 和系统进程创建标识共同确认，不再根据“端口有人监听”自动接管。启动记录保存在 `data/process-ownership.json`；PID 被复用或服务端路径变化时不会误认。已有外部启动的服务端，或更新前没有身份记录的旧进程，会显示“端口冲突”：请先从原控制台正常停服，再由面板启动。若面板重启后无法恢复原进程的标准输入，也不会向未知进程发送指令。

## Mod、插件与文件管理的安全策略

- “停用”会把 JAR 移到服务端的 `disabled_mods` 文件夹。
- “移除”会把 JAR 移到 `.ripple-panel/mod-trash`，不会永久删除。
- 从回收站恢复时先恢复为停用状态，确认无误后再启用。
- 面板只能读取常见 Mod 元数据，不能保证依赖完整或客户端/服务端兼容。
- 插件使用独立的 `plugins`、`disabled_plugins` 和插件回收目录，不会与 Mod 混用。
- 文件编辑前自动保存历史版本；网页删除会移动到面板内部回收站。
- 编辑会话绑定实例和原文件版本；切换实例时清空会话，未保存内容需要确认，外部修改后的旧版本不能直接覆盖新内容。
- 文本编辑保留 UTF-8 BOM 和 Windows CRLF 换行；BAT/CMD 保存为 CRLF。不支持的非 UTF-8 文件需要下载后用本地编辑器修改。
- 文件 API 会把所有路径解析并限制在当前服务端根目录，面板内部数据不会暴露给文件管理器。

更换 Mod 前请先停止服务器并创建世界备份。

## 备份

备份默认保存在每个服务端的：

```text
panel-backups/
```

备份包含 `level-name` 指定的世界文件夹、同名 `_nether` / `_the_end` 世界，以及根目录中含 `level.dat` 的附加世界；也包含白名单、OP、封禁和 `server.properties`。这不是整个服务端的镜像，不包含所有 Mod、插件和它们的数据；非标准世界路径需要另行核对备份范围。

备份先写入 `.partial` 临时文件，生成完成清单与逐文件 SHA-256，读回校验成功后才发布为 ZIP。缺少世界、空间不足或压缩中断会明确失败，不会把半成品当作可恢复备份。在线备份会等待新日志中的保存完成确认，最后恢复自动保存；若确认超时，页面会提醒检查控制台或改用正常停服后的离线备份。若提示未确认恢复自动保存，请立即在控制台核实并执行 `save-on`。

旧 ZIP 文件会保留并标为“未验证”，仍可下载；由于无法证明它原先是否完整，不再直接自动恢复。新备份恢复前会重新检查清单、哈希与空间。恢复要求先停服，与启动、重启、备份共用实例维护锁，排队期间也不能启动服务器。被替换的现有世界和配置会保留在 `.ripple-panel/restore-history`。

超出实例“保留备份数”的旧备份会移入 `panel-backups/.trash`。回收站和恢复历史仍占磁盘空间；请确认不再需要后自行清理，面板不会为释放空间而直接永久删除这些历史。

“自动化”页可以为每个实例单独设置备份间隔和每天重启时间。计划由本地面板进程执行，因此面板窗口必须保持运行；电脑关机、睡眠或面板关闭期间不会执行任务。所有计划默认关闭，启用自动备份时从当前时间开始计算第一次间隔。

性能历史由后端每 10 秒采样，不再依赖浏览器是否打开；面板退出后不采样。浏览器与面板断开时会标注数据失效并停用主要控制按钮，FRP 进程运行也不会被等同于外网已连通。

## 游戏规则

“游戏规则”页通过当前服务端控制台实时执行原版命令，可以调整时间、天气、难度、死亡保留物品、生物破坏、昼夜与天气循环、火焰蔓延和入睡比例，也可以向所有在线玩家发送公告。使用这些操作时服务端必须处于运行状态。

## 运行诊断

“运行诊断”页会读取当前 Java 版本、加载器、Mod 数量、磁盘空间、上次退出状态、`logs/latest.log` 中最近的高信号错误行，以及 `crash-reports` 目录中的报告。面板会优先给出一个可执行的自动结论，目前可识别仅客户端 Mod、端口占用、内存不足、Java 版本和 Mod 依赖问题。诊断摘要可以复制，崩溃报告可以逐个下载；内容只在本机处理，不会上传。

市场面板功能对照与本项目的取舍见 [`docs/MARKET_RESEARCH.md`](docs/MARKET_RESEARCH.md)。

## 安全说明

网页控制台等同于 Minecraft 服务端管理员权限。项目采取了以下本地安全限制：

- 默认仅绑定 `127.0.0.1`
- POST 请求验证 `Host` 与 `Origin`
- 不启用 CORS
- 严格限制可访问路径、Mod 文件名和启动目标
- CSP、`X-Frame-Options: DENY` 与禁止浏览器敏感权限
- 删除类功能优先移动到回收目录

如果主动把面板监听地址改为 `0.0.0.0`，必须自行增加身份验证、HTTPS 与反向代理访问控制。本项目当前不建议这样使用。

## 项目结构

```text
Lodestar/
├─ server.py                 # 标准库后端、进程与文件管理
├─ server_bootstrap.py       # 官方依赖下载、Java 匹配、整合包一键准备
├─ static/
│  ├─ index.html             # 面板页面
│  ├─ app.css                # 基础组件与响应式布局
│  ├─ editorial.css          # 暖色编辑风格与深色主题
│  ├─ report-theme.css       # 侧栏工作台、紧凑概览与主题覆盖
│  ├─ studio-art.css         # 原创插画、暖纸/深林主题与视觉细节
│  ├─ studio-art.js          # 装饰图挂载；不调用服务端 API
│  ├─ app.js                 # 前端状态和 API 调用
│  └─ assets/                # 品牌素材；studio/ 内为 8 张新版原创 PNG
├─ data/
│  └─ settings.example.json  # 空白配置示例
├─ 启动面板.bat
├─ start.sh
└─ README.md
```

## 回归测试

测试使用独立临时服务端目录与模拟进程，不操作现有游戏服：

```bash
python -B -m unittest discover -s tests -v
node tests/test_frontend.cjs
node --check static/app.js
node --check static/studio-art.js
```

Node.js 仅用于开发期前端测试，日常运行面板不需要安装。
