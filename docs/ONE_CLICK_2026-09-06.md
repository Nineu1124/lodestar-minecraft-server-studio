# Lodestar 3.1 · 一键开服

## 怎么用

1. 双击 `启动面板.bat`，进入本机面板。
2. 新包：导入服务端 → 选择 ZIP → 检查 → 保留“一键推荐”，确认新目录、内存和端口，明确勾选 EULA 与信任下载 → 一键开服。已有实例直接点“一键开服”。
3. FTB：选择“FTB 官方整合包”，填写项目 ID 和新目录。版本 ID 可留空取官方稳定发布版；任务开始后固定具体版本。Evolution 的验证组合为 `125 / 100487`。

自动流程按阶段完成“识别版本 → 验证/选择 Java → 下载或安装核心 → 加载模组和世界 → 确认游戏状态”。只有收到两次结构完整的 Minecraft 状态响应才将开服任务标记为完成，不以端口打开或一条 `Done` 日志提前宣布成功。

## 支持范围

| 包/格式 | 自动处理 |
| --- | --- |
| 带可靠版本元数据的 Forge / NeoForge / Fabric 服务端 | 从安装器名、参数文件或 ServerPackCreator `variables.txt` 获取固定版本，安装官方核心 |
| GTNH Java 17+ 服务端 | 使用 Java 17，保留 `java9args.txt` 与必要超时参数，不因 Minecraft 1.7.10 误选 Java 8 |
| 官方 RLCraft 2.9.3 服务端 ZIP | 仅对已核对 SHA-256 的原始发布包补装 Forge 14.23.5.2860 / Java 8；不凭文件名猜版本 |
| FTB 官方服务端 | 读取官方发布清单，排除 client-only 文件，逐一验证哈希后安装对应核心；续装保持固定版本 |
| Luminara / Arclight / Mohist 等混合核心、其他已有启动方式 | 保留原配置，不擅自替换核心；可使用手动启动模式 |

这不是通用客户端整合包转换器，不自动解决任意 Mod 冲突或移除模组。无可靠元数据、作者特殊启动器、未来加载器版本可能需要人工配置。Windows x64 自动便携 Java 已实现；其他系统须自行提供相应 Java。

## 数据与控制边界

- 只操作用户选择的新目录或当前实例。正式世界、FRP、DNS、防火墙、系统 Java/PATH 不随功能升级更改。
- EULA 与代码信任选项默认不勾选。运行 Mod/作者脚本不是安全沙箱，应仅导入可信来源。
- 面板直接下载限制为官方 HTTPS 分发站点，并检查重定向；Java、Forge/NeoForge 安装器及 FTB 文件验证官方校验值。Fabric 启动器来自官方 HTTPS API。安装器/游戏自身仍会联网获取其依赖。
- 便携运行时：`data/bootstrap-cache`。核心安装日志：实例 `.lodestar/install.log`。中断安装有独立标记，参数文件提前出现也不会误判安装完毕。
- 取消时尝试正常停止本任务启动的游戏进程，保留已经下载的文件与世界。不会强制杀掉其他实例。未完成解压的临时目录沿用原有失败清理机制。
- 失败后的已导入实例直接点“一键开服”重试。FTB 首次文件下载未完成时会重新校验作者清单文件；此阶段不要手动修改这些文件。完成后再次开服不会重新同步或升级整合包。
- UI 支持精确任务轮询、准备进度、取消与失败提示。刷新页面后，可在已注册的对应实例查看仍在执行的任务；ZIP 尚在解压、还未生成实例时，应保留导入页面，若已刷新可稍后再刷新以加载新实例。重启面板会丢失内存中的任务进度，不建议准备期间关闭面板；保留的实例/文件可供下次重试。

本次使用独立数据目录、新测试世界、回环地址和 `25861–25866` 端口。在线认证/白名单开启，Query/RCON 关闭；逐个启动，不改两台正式实例。

88 项后端/HTTP 测试与 22 项前端测试通过，涵盖版本识别、真实 Java 版本选择、安装中断重试、下载哈希、路径/URL 限制、原核心保留、任务取消、EULA/信任校验、严格状态解析、HTTP 路由以及前端任务状态。

通过独立浏览器预览检查了压缩包识别、一键/自定义切换、FTB 表单和默认未勾选的协议/信任选项；修正了三个导入入口的布局，浏览器未见 JavaScript 报错。正式面板已重启至 3.1.0，两个正式实例仍停止，`data/settings.json` SHA-256 与升级前完全一致。
